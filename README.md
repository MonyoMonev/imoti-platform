# Платформа за агенция за имоти

Сайт за агенция за недвижими имоти с админ панел: имоти, брокери, линкове за социалните мрежи,
чат помощник с въпроси и готови отговори, запитвания към брокера и анализ за собственика.

## Пускане

```
npm install
npm run dev        # разработка, http://localhost:3210
npm run demo       # бърз вариант за показване (build + start)
```

Нищо друго не е нужно. Базата е PostgreSQL, вграден в самото приложение (PGlite), и се създава
сама при първото отваряне заедно с примерните данни. Файловете ѝ са в `.data/`.
`npm run db:reset` я връща в начално състояние.

## Трите достъпа

* **Шеф**: всичко. Кани брокери с код, спира им достъпа, разпределя запитвания, вижда анализа
  на чата (кой докъде е стигнал и защо се е отказал), всички клиенти, имоти и известия.
* **Брокер**: своите запитвания, своите имоти, линкове за споделяне на който и да е имот от свое
  име, своите клиенти, известия и профил.
* **Клиент**: профил на сайта със запазени имоти, запитвания и последно разгледани.

## Как е подредено

```
src/lib/brand.ts        името, телефонът, адресът и етажите на началната страница
src/lib/chat-tree.ts    въпросите на чата (данни, не код)
src/lib/schema.ts       таблиците
src/lib/seed.ts         примерните брокери, имоти и активност
src/lib/notify.ts       известието до брокера (Viber, Telegram или симулация)
src/app/(site)          публичният сайт
src/app/admin           админ панелът
src/app/api             сървърните адреси
tests/                  автоматичните тестове
```

Линк за социалните мрежи: `/oferta/<брокер>/<имот>?k=fb` (fb, ig, tt, viber). Прави се от
„Линкове за споделяне“ в панела.

## Тестове

Пускат се срещу работещ сървър с прясна база.

```
node tests/admin.mjs      # админ панел, роли и права (ADMIN_URL=http://localhost:3210)
node tests/e2e.mjs        # публичен сайт, чат, профили, телефон
node tests/cross.mjs      # запитванията от чата стигат до правилния брокер (след e2e)
```

## Какво е симулирано в демото

* **Viber**: всеки брокер свързва свой частен Viber канал от „Моят профил“ (токен от
  „Developer Tools“ в канала) и новите запитвания се публикуват там. Който не е свързал канал,
  не получава нищо на телефона: съобщението само се пази в „Известия“. Свързването работи от
  качения сайт, защото Viber иска https адрес. Тест с имитация на Viber: `node tests/viber.mjs`.
* **Снимки и хора**: стокови снимки (списък в `public/img/CREDITS.md`) и измислени брокери.
* **Активност**: един месец примерни посещения, чатове и запитвания. Трие се от Настройки.

## Качване в облака (Vercel)

Кодът е готов за това и е тестван върху истински PostgreSQL (Neon и локален Postgres 15).
Нова версия се качва от тази папка с `npx vercel deploy --prod --yes`.
Проверка на качен адрес: `node tests/live.mjs https://<адрес>` (оставя едно пробно запитване
„Проба Демо“, което после се трие от базата).

* `DATABASE_URL` към Postgres (Supabase или Neon). Таблиците и примерните данни се създават
  сами при първото отваряне. При Supabase се ползва адресът на pooler-а, не директният.
* Качените снимки се пазят в базата (таблица `media`), защото сървърът в облака няма диск.
* `SITE_URL` с истинския домейн. Без него се взима адресът, който Vercel дава на проекта.
* `ALLOW_INDEX=1`, когато сайтът трябва да се вижда от търсачките. Дотогава е скрит.
* `HIDE_DEMO_LOGIN=1` скрива бутоните за бърз вход в панела.
* `vercel.json` държи сървъра във Франкфурт, близо до базата.
